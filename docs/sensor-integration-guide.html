Integrating a New I2C Sensor
Day 2 — Independent Work Guide

Microcontrollers Workshop
Adafruit Feather Logger
Your goal today: Find a sensor from the kit that interests you, wire it up, and get it logging alongside the temperature & humidity data you set up yesterday. Work through these steps in order. Each step has a checkpoint — don't skip ahead until you've hit it. Ask for help when you're stuck, but try the troubleshooting tips first.

Step-by-Step

1

Pick your sensor

Look through the I2C sensor kit. Choose one that seems interesting — don't overthink it. Some popular options that work well:

  • BME280 — barometric pressure + altitude
  • APDS-9960 — color and gesture detection
  • LSM6DS3 / MPU-6050 — accelerometer (detects movement and orientation)
  • VL53L0X — laser distance sensor
  • SGP30 — air quality (CO₂, VOC)

Write down the exact part number printed on the sensor chip or breakout board label. You'll need this in the next step.

You know your sensor's part number and you find it genuinely interesting.
2

Find the Arduino library

In the Arduino IDE, open Tools → Manage Libraries. Search for your part number.

  • Look for a library published by Adafruit or SparkFun — these are well-maintained and come with examples.
  • If you see multiple results, pick the one whose name most closely matches your part number.
  • Click Install. If it asks about installing dependencies, click Install All.
If you can't find your sensor in the library manager, search the web for "[part number] Arduino library". The manufacturer usually has a GitHub page with install instructions.
The library is installed and you can see it listed under Sketch → Include Library.
3

Wire up the sensor

I2C sensors use four wires. Connect them as follows:

Sensor pin Feather Logger pin What it does
VIN or VCC3.3VPower
GNDGNDGround
SDASDAData
SCLSCLClock
The SDA and SCL pins on your Feather are already used by the temperature sensor. That's fine — I2C is a bus, meaning many sensors can share the same two wires. Just make sure all sensors share the same SDA, SCL, 3.3V, and GND.
All four wires are connected securely. The board powers on without any smoke or burning smell.
4

Run the example sketch

Before touching your logging code, verify the sensor works on its own.

Go to File → Examples and find your sensor's library in the list. Open the example called something like basicreadings, demo, or test.

Upload it and open Tools → Serial Monitor (make sure the baud rate at the bottom right matches the Serial.begin() value in the sketch, usually 9600 or 115200).

If you see garbled text in the Serial Monitor, the baud rate doesn't match. Check the number in Serial.begin(____) and set the dropdown to match.
You can see real sensor readings scrolling in the Serial Monitor, and they change when you interact with the sensor (wave your hand near it, breathe on it, tilt it, etc.).
5

Understand what the example is doing

Before merging, spend 5 minutes reading through the example code. Look for answers to these questions — write them down if it helps:

  • What does the #include line at the top say?
  • How is the sensor object created? (Usually something like SensorName mySensor;)
  • What happens in setup()? (Initialization — this runs once)
  • What function reads the sensor data in loop()? (e.g. mySensor.readTemperature())
  • What variable holds the reading, and what are its units?
You can point to the one or two lines in the example that actually read the sensor value and explain in plain English what they do.
6

Merge your sensor into the logging sketch

Open your logging code from yesterday. You need to add four things from the example — think of it as transplanting pieces in order:

① At the very top — include & object

Copy the #include line and the sensor object declaration from the example into the top of your logging sketch.

// Already in your sketch:
#include <Adafruit_SHT31.h>
Adafruit_SHT31 sht31;

// Add below it (example — yours will differ):
#include <Adafruit_BMP280.h>
Adafruit_BMP280 bmp;

② Inside setup() — initialization

Copy the sensor's initialization block (usually an if (!sensor.begin()) check) into your setup(), after your existing sensor's init.

// Example:
if (!bmp.begin()) {
  Serial.println("Could not find BMP280!");
  while (1);  // stop here if sensor not found
}

③ Inside loop() — read the value

Where you currently read temperature and humidity, add lines to read your new sensor. Store the result in a variable.

float pressure = bmp.readPressure() / 100.0;  // hPa

④ In the SD logging line — add the new column

Find where you write a line to the SD card. Add your new value, separated by a comma.

// Before:
dataFile.println(String(temp) + "," + String(humidity));

// After:
dataFile.println(String(temp) + "," + String(humidity) + "," + String(pressure));
Your sketch compiles without errors (Sketch → Verify/Compile). Fix any red error messages before uploading.
7

Test it

Upload the merged sketch. Open the Serial Monitor and confirm you can see readings from both sensors printing together. Let it run for 30 seconds and make sure there are no error messages.

Then wipe the SD card, restart the board, and let it log for a minute. Remove the card, open the CSV file on a computer, and verify all your columns are there and the values look reasonable.

Your CSV has a row for every logging interval and your new sensor's column is populated with real values.
8

You're done — what's next?

If you've got time and want to go further, pick one:

  • Add the I2C screen — display your new sensor's reading live on the display
  • Add the RTC — give each row of your log file a real timestamp
  • Add a second new sensor — repeat this whole guide from Step 1
  • Write a graphing script — plot your new data column alongside temperature

Troubleshooting

Symptom Most likely cause Try this
Serial Monitor shows nothing Baud rate mismatch, or wrong port Check Serial.begin() value matches the Serial Monitor dropdown. Check Tools → Port.
"Could not find sensor!" on startup Wiring error or wrong I2C address Double-check SDA/SCL connections. Run the I2C Scanner sketch to confirm the sensor is visible on the bus.
Sketch won't compile — red errors Missing library or typo Read the first error carefully — it usually says exactly what's missing. Re-check your #include line matches the library name exactly.
Sensor reading is always 0 or NaN Sensor initialized but not reading correctly Go back to the plain example sketch. If it works there, compare your merge carefully — likely a missing variable or the read function wasn't called.
SD card file is missing the new column Forgot to update the logging line Search your code for dataFile.println and make sure your new variable is included in the string.
Two sensors, one stops working I2C address conflict Some sensors share a default I2C address. Ask a mentor — the fix usually involves soldering an address-select pad on the breakout board.

Quick Reference — I2C Scanner Sketch

If you're not sure your sensor is wired correctly, upload this sketch. It will print the I2C address of every device it finds. A healthy system should show one address per sensor.

#include <Wire.h>

void setup() {
  Wire.begin();
  Serial.begin(9600);
  Serial.println("Scanning I2C bus...");

  for (byte addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);
    if (Wire.endTransmission() == 0) {
      Serial.print("Found device at address 0x");
      Serial.println(addr, HEX);
    }
  }
  Serial.println("Done.");
}

void loop() {}
